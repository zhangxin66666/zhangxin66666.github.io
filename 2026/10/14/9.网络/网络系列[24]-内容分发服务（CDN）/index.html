网络系列[24]-内容分发服务（CDN）

利用内容分发服务器分担负载

缓存服务器部署在不同位置会带来不同的效果。如图 a) 所示，当缓存服务器位于服务器端时，可有效减轻 Web 服务器的负载，但对互联网整体流量的减少作用有限。相较之下，将缓存服务器部署在客户端侧（图 b)）则能显著降低网络传输量。

互联网中常存在拥塞节点，数据包在这些节点处传输延迟较大。若缓存服务器位于客户端侧，可在本地直接响应请求，从而减少经过拥塞点的频率，使网络通信更加稳定。尤其是在访问包含大量图片或视频等大流量内容时，这种部署方式的效果更为明显。

然而，客户端侧的缓存服务器通常由客户端网络运营管理者控制，Web 服务器的运营方无法直接管理。例如，当网站内容增多导致缓存空间不足时，如果缓存服务器部署在服务器端，运营方可通过扩容磁盘等方式灵活调整；而位于客户端侧的缓存服务器则无法直接扩容，甚至部分客户端网络可能并未配置缓存服务器。

综上所述，缓存服务器部署在服务器端与客户端各有优劣。为兼顾两者的优势，可采用如图 c) 所示的混合方式：由 Web 服务器运营方与网络运营商签约，将可由自身控制的缓存服务器部署在运营商的网络节点处。这样既能让缓存服务器更靠近用户，提升访问效率，又能保持对缓存服务器的管理和控制。

不过，该方案在实际部署中面临挑战。由于互联网中的服务器面向全球开放访问，若要全面覆盖用户请求，需在各主要运营商的接入点（POP）中都部署缓存服务器，数量巨大，实施成本极高。

为降低部署成本，可仅选择部分主要运营商进行合作。尽管这样会导致部分用户访问缓存服务器的路径仍然较长，但整体访问距离依然短于直接访问 Web 服务器，性能上仍具明显优势。

即便如此，Web 服务器运营方若单独与多家运营商签约并自行部署缓存服务器，仍会在费用与运维精力上面临巨大压力。为此，出现了专门提供缓存分发服务的厂商——内容分发服务提供商（CDSP）。

CDSP 通常会与各大运营商签约，并在其网络中部署大量缓存服务器；同时再与 Web 服务器运营方签约，使这些缓存服务器与目标网站协同工作。

当客户端访问某一网站时，实际上访问的可能是 CDSP 的缓存节点，而非网站自身的主服务器。

CDSP 的缓存服务器可同时为多个网站提供服务，实现资源共享。通过这种方式，各网站的平均成本显著降低，运维压力也随之减轻。同时，CDSP 统一负责与各运营商的合作与节点维护，使网站运营方能够专注于内容运营与业务优化。

如何找到最近的缓存服务器

在内容分发服务（CDS）中，互联网中分布着大量缓存服务器。为了提高访问速度，必须使客户端能够自动连接到距离最近的缓存服务器。

若依赖浏览器中的代理设置虽然可以实现这一目标，但显然无法让所有用户手动配置。因此，需要一种无需用户干预、即可将请求自动路由到最近缓存服务器的机制。

常见的实现方法之一是利用 DNS（域名系统） 进行访问分配，其原理与负载均衡类似。DNS 服务器在返回 Web 服务器 IP 地址时，可以对响应内容进行“加工”，使返回结果为距离客户端最近的缓存服务器的 IP 地址。

在介绍这种机制的细节前，先回顾 DNS 的基本工作过程。

DNS 的基本工作方式

互联网中部署着大量 DNS 服务器，它们通过逐级解析的方式完成域名查询。

  1. 客户端首先根据要访问的 Web 服务器域名生成查询请求，并将该请求发送至本地局域网中的 DNS 服务器（图①）。
  2. 本地 DNS 服务器根据域名的层级结构逐步定位到负责管理该域名的权威 DNS 服务器（即 Web 服务器侧的 DNS 服务器），并将查询请求转发给它（图②）。
  3. Web 服务器端的 DNS 服务器收到查询后，从内部维护的域名与 IP 地址对应表中查找匹配记录，并返回相应的 IP 地址（图③）。
  4. 查询结果沿反向路径依次返回给本地 DNS 服务器，最终再返回给客户端（图④）。

通常情况下，一个域名只对应一个 IP 地址。但若配置了多个 IP 地址，DNS 服务器往往会采用轮询（Round Robin）的方式依次返回各个地址，从而在多台服务器之间分散访问负载。

基于距离的 DNS 解析策略

在标准的 DNS 工作机制下，返回 IP 地址的顺序与客户端和服务器之间的物理或网络距离无关，因此可能导致客户端连接到较远的缓存服务器。

为了让用户始终访问距离最近的缓存节点，DNS 服务器需要根据客户端与各缓存服务器的网络距离来决定返回的 IP 地址。

关键问题在于如何判断客户端与缓存服务器之间的距离。解决方法如下：

  1. 路由信息收集

事先从缓存服务器部署地点的路由器中收集路由表信息。

假设共有 4 台缓存服务器，分别部署在 4 个不同地点，则需要从这 4 个地点的路由器分别导出路由表，并集中存放在 DNS 服务器中。

  1. 距离估算与比较

当 DNS 服务器接收到来自客户端 DNS 服务器的查询消息时，可利用这些路由表信息推测网络距离。

例如，根据路由器 A 的路由表可以查出，从路由器 A 到查询发起方（客户端 DNS 服务器）所经过的路径，如：先通过运营商 X，再经过运营商 Y，最终抵达运营商 Z。

通过对比这些路径的网络跳数、自治系统（AS）路径或延迟指标，即可大致判断各路由器（也即各缓存服务器位置）到客户端的远近关系。

  1. 返回最优结果

比较所有缓存服务器的路径距离后，DNS 服务器选择距离最近的缓存服务器，并将其 IP 地址作为解析结果返回。客户端随后即可通过该地址访问相应的缓存节点。

需要注意的是，客户端 DNS 服务器与实际客户端可能并非处于完全相同的地理或网络位置，因此该方法的距离估算并不完全精准。但在绝大多数情况下，基于路由信息的判断仍能获得较为理想的分配效果。

通过重定向服务器分配访问目标

除了利用 DNS 分配访问外，还可以通过 HTTP 重定向（Redirect） 的方式，使客户端自动访问距离最近的缓存服务器。

在 HTTP 协议中定义了多个头部字段，其中的 Location 字段用于指示资源已被转移至其他服务器。当 Web 服务器返回包含 Location 字段的响应时，表示资源位置已更改，客户端应按照该字段指定的地址重新发起请求。

这种引导客户端访问其他 Web 服务器的机制即为 重定向。利用该机制，可将客户端访问请求转发至最近的缓存服务器。

重定向的工作过程

当使用重定向实现缓存服务器的分配时，首先需在 Web 服务器端的 DNS 中注册一台 重定向服务器。客户端在解析域名后，会将 HTTP 请求发送至这台重定向服务器。

重定向服务器与基于 DNS 分配方法中的 DNS 服务器类似，同样需要预先收集来自各个缓存服务器部署地路由器的路由信息。

当接收到客户端的 HTTP 请求后，重定向服务器根据这些路由信息计算客户端与各缓存服务器之间的距离，选出最近的缓存节点，并在响应中返回 Location 字段，指向该缓存服务器的地址。客户端接收到响应后，会根据该字段重新向缓存服务器发起访问请求。

方法比较与精度分析

与基于 DNS 的方法相比，重定向方式虽然增加了一次 HTTP 消息交互，通信开销略高，但在精度上具有明显优势。

DNS 方式依赖的是 客户端 DNS 服务器 与缓存服务器之间的距离估算，而重定向方式可以直接依据 客户端 IP 地址 计算到各缓存服务器的距离，因此判断结果更为准确。

精度提升与扩展方式

重定向服务器除可依赖路由信息进行距离估算外，还可结合其他实时网络特征以进一步提高准确度。

例如，服务器可以返回一段用于测量网络延迟的脚本。客户端执行脚本后，会向多台缓存服务器分别发送测试包（如 ICMP 或 HTTP 请求），测量各节点的往返时间（RTT），并自动选择响应最快、延迟最低的服务器作为访问目标。

这种方式能够动态地反映网络状态，从而更精确地将客户端引导至性能最优的缓存服务器，实现更高效的内容分发。

缓存更新方法会影响性能

缓存服务器的核心思想，是将曾经访问过的数据临时保存下来，在后续访问相同内容时直接提供缓存结果，以提升访问效率，这一机制可显著降低对原始服务器的访问频率。

然而，这种方式存在两个局限：

  1. 首次访问无法命中缓存。
  2. 在后续访问中，需要频繁向原始服务器确认数据是否更新。当网络出现拥塞时，这类验证操作会导致响应时间明显延长，从而削弱缓存带来的性能提升。

主动更新机制

为改善上述问题，可采用 主动更新（Push-based Invalidation） 机制。

该方法由 Web 服务器在原始数据发生变更时主动通知缓存服务器，使其立即更新对应的缓存内容。通过这种方式，缓存服务器始终持有最新数据，无需在每次访问时与原始服务器进行一致性确认。

同时，缓存服务器在收到通知后即可直接响应请求，因此从第一次访问起便能发挥缓存加速效果。

在内容分发服务（CDS）体系中，部署的缓存服务器通常具备此类主动同步能力，以确保分发内容与源站保持一致。

动态内容的缓存策略

除了静态内容外，部分 Web 页面由 CGI、Servlet 或其他动态程序在接收请求后即时生成，这类 动态页面（Dynamic Content） 无法直接缓存。

针对这种情况，可将页面内容划分为两部分：

  • 静态部分：如页面框架、样式表、图片等不随请求变化的内容，可安全地缓存；
  • 动态部分：由应用程序生成、在每次请求中变化的数据，不进行缓存。

通过这种 静态与动态分离（Static-Dynamic Separation） 策略，可在保持页面灵活性的同时，最大化缓存服务器的性能收益。

请求路径中的缓存角色

在典型的 Web 架构中，请求消息在到达 Web 服务器之前，会依次经过多种中间节点，如防火墙、代理服务器及缓存服务器等。

Web 服务器在接收到请求后，会解析请求内容，生成对应的响应消息并返回。若缓存服务器具备最新内容，可在请求到达 Web 服务器之前直接响应，从而显著降低服务器负载并改善整体响应速度。
