网络系列[7]-通过ARP查询目标路由器MAC地址

发表于2026-10-14|更新于2026-10-14|9.网络
|字数总计:545|阅读时长:1分钟|阅读量:

在构建以太网帧的过程中，我们需要在 **IP 包前面加上以太网头部 (MAC 头部)**，它属于 数据链路层的控制信息。

这个头部主要包含以下三个关键字段：

  1. 目的 MAC 地址 (Destination MAC Address)
  • 表示数据帧要交付的下一个设备。
  • 在主机发送数据时，通常并不知道最终目的 IP 对应的 MAC 地址，而是根据路由表确定“下一跳”的 IP 地址。
  • 拥有下一跳 IP 后，可以通过 ARP 协议查询出对应的 MAC 地址。
  1. 源 MAC 地址 (Source MAC Address)
  • 表示发送该数据帧的网卡 MAC 地址。
  • 如果主机有多个网卡，就使用实际承担发送任务的那块网卡的 MAC 地址。
  1. 以太类型 (EtherType)

  • 表示上层协议类型，告诉接收方该帧的有效载荷是什么协议的数据。

  • 常见取值：

  • 0x0800 → IPv4

  • 0x0806 → ARP

  • 0x86DD → IPv6

ARP 的作用

ARP (Address Resolution Protocol) 用于在同一局域网中，将 IP 地址解析为 MAC 地址。

工作方式：

  • 当主机不知道下一跳 IP 对应的 MAC 地址时，会发送一个 广播 ARP 请求。
  • 局域网中所有设备都会收到该请求，只有 IP 匹配的设备才会回应自己的 MAC 地址。
  • 发送方收到应答后，就可以用这个 MAC 地址填充以太网头部中的 目的 MAC 地址。

ARP 缓存

  • 为了避免每次都广播查询，主机会维护一个 ARP 缓存表。
  • 当需要解析某个 IP 地址时，优先查询缓存，如果命中则直接使用；
  • 如果未命中，才触发真正的 ARP 请求。
  • 缓存条目会有过期时间（通常几分钟），以防止 IP 地址变化导致“脏数据”。

关键点总结

  • 以太网头部：目的 MAC、源 MAC、以太类型。
  • 下一跳 MAC 的获取：通过路由表找到下一跳 IP → ARP 解析出 MAC。
  • ARP 缓存：提升性能，避免频繁广播。
  • IP 模块的职责：IP 层决定发给哪个下一跳，链路层填充 MAC 头，最后由网卡完成数据帧的发送。
