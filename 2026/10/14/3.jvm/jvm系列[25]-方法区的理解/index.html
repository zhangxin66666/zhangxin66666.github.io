1. 方法区的演变

在 HotSpot JVM 中，方法区（Method Area） 存储 类的元信息（例如类的结构、字段、方法、常量池等），在 Java 8 之前，它的实现依赖于永久代（PermGen），而 Java 8 以后则采用了元空间（Metaspace）。

JVM 版本

方法区实现

主要存储内容

分配方式

Java 6 及以前

永久代（PermGen）

类的元数据、运行时常量池、方法信息、静态变量、字符串常量池

受 JVM 内存 限制，容易 OOM

Java 7

仍然是永久代，但部分数据迁移到了 Java 堆

字符串常量池、静态变量迁移到 Java 堆，但类元数据仍在永久代

改善了一些 OOM 问题，但仍有永久代大小限制

Java 8 及以后

元空间（Metaspace）

类的元数据存储在本机直接内存，但静态变量和字符串常量池仍然在 Java 堆

使用 本机内存（不受 JVM 限制），避免 OOM，但可能导致无限增长

2. Java 7 的永久代优化

在 Java 7 时，为了减少永久代的内存管理问题，部分数据被移出了永久代：

  1. 字符串常量池（String Pool）
  • Java 6 及以前：字符串常量池存储在永久代，导致 Interned String 可能会导致 OutOfMemoryError。
  • Java 7：字符串常量池被移动到 Java 堆，解决了永久代 OOM 问题，并使得字符串管理更加灵活。
  1. 静态变量（Static Variables）
  • Java 6 及以前：类的 静态变量（static 变量） 存储在永久代。
  • Java 7：静态变量被移到 Java 堆，减少了永久代的负担。

Java 7 仍然保留了永久代，但它的负担减轻了一些。

3. Java 8 正式移除永久代

Java 8 彻底移除了永久代（PermGen），引入了元空间（Metaspace）。
永久代剩余的内容（如类的元信息、方法信息等）被迁移到了 元空间（Metaspace），并且存储在本机直接内存（Native Memory），不再受 JVM 内存的限制。

元空间（Metaspace）主要的特点

  • 使用本机内存（Native Memory），而不是 JVM 的堆内存：

  • 永久代的大小由 -XX:MaxPermSize 控制，但元空间的大小默认只受本机可用内存的限制，当然你可以用 -XX:MaxMetaspaceSize 来控制。

  • 这样可以避免永久代 OOM，但可能导致元空间无限增长，如果元空间不受限制，会导致系统内存耗尽。

  • 类的元数据（Class Metadata）全部存储在元空间：

  • Java 8 后，类的元数据（包括方法、字段等信息） 从永久代迁移到了元空间。

  • 但静态变量仍然存储在 Java 堆。

  • 运行时常量池（Runtime Constant Pool）仍然在 Java 堆：

  • Java 7 之后，运行时常量池 不再存放在永久代，而是存放在 Java 堆，避免了早期 JVM 因过多 intern() 操作导致 OOM 的问题。

4. 总结

JVM 版本

存储方式

存储内容

Java 6 及以前

永久代（PermGen）

类元数据、运行时常量池、方法信息、静态变量、字符串常量池

Java 7

部分优化（仍然是永久代）

字符串常量池、静态变量移至 Java 堆，但类元数据仍在永久代

Java 8 及以后

元空间（Metaspace）

类元数据存储在元空间（本机内存），静态变量和字符串常量池仍然在 Java 堆

所以：

  1. Java 7 只是优化了部分永久代的存储，而 Java 8 彻底移除了永久代，改用元空间。
  2. 元空间使用的是本机内存，而不是 JVM 管理的堆内存，所以不再受到**-XX:MaxPermSize**限制，但仍可以使用**-XX:MaxMetaspaceSize**进行限制。
  3. 字符串常量池、静态变量等已经迁移到 Java 堆，减少了方法区的负担。
