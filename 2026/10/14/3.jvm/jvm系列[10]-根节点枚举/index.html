jvm系列[10]-根节点枚举

发表于2026-10-14|更新于2026-10-14|3.jvm
|字数总计:802|阅读时长:2分钟|阅读量:

根节点枚举（Root Set Enumeration）是垃圾回收（GC）过程中至关重要的步骤，它决定了 GC 从哪些对象开始遍历和标记。截至目前，所有的收集器在根节点枚举这一步都是必须暂停用户线程的（STW），现在可达性分析算法最耗时的查找引用链的过程已经可以做到与用户线程一起并发，但是根节点枚举必须在一个能保障一致性的快照中才得以进行。这是导致垃圾收集过程必须停顿所有用户线程的一个重要原因。

如果在分析过程中根节点集合的对象引用关系还在不断变化，那分析结果的准确性也就无法保证。

传统方法需要 完整扫描整个堆栈和寄存器，但这会导致长时间的 STW，因此 HotSpot 通过 OopMap 和 Safepoint 机制 进行优化。

1.OopMap 机制

OopMap 是 HotSpot 在 JIT 编译 时生成的数据结构，它记录了某些特定程序计数器（PC）位置的对象引用信息，使 GC 能够直接获取 GC Roots，而不需要完整扫描所有栈帧。

(1) OopMap 的构建

  • 在 C1/C2 JIT 编译器 编译字节码时，会记录方法调用或某些特定指令处的引用信息，存入 OopMap。

  • 这些记录的信息包括：

  • 寄存器中存在哪些对象引用

  • 栈帧的哪些槽位（slot）存储了对象引用

  • 固定偏移量，帮助 GC 快速索引

示例：

当 GC 触发时，HotSpot 不需要扫描整个栈，而是直接利用 OopMap 读取 GC Roots，大幅减少枚举时间。

(2) OopMap 结合 Safepoint

  • Safepoint 是 HotSpot 设定的代码执行停顿点，GC 只能在 Safepoint 处暂停线程并枚举根节点。
  • 线程执行时不会频繁检查 GC，而是在 Safepoint 处检查并暂停，然后使用 OopMap 快速获取 GC Roots。

2. 各 GC 方案的根节点枚举

不同 GC 使用 OopMap 并结合自己的优化策略来减少 STW 时间：

(1) G1 GC：Remembered Set + SATB

  • G1 GC 主要依赖 Remembered Set 和 SATB（Snapshot-At-The-Beginning） 机制：

  • Remembered Set 记录跨分区引用，避免全局扫描。

  • SATB 允许在并发标记时保留对象原始引用，减少 GC Roots 的误差。

  • 根节点枚举过程：

  1. STW 时使用 OopMap 读取 GC Roots。
  2. 结合 Remembered Set，追踪跨 Region 的引用。
  3. 进入 并发标记 阶段，继续处理可达对象。

(2) ZGC：读屏障 + 并发根节点扫描

  • ZGC 采用 完全并发的 GC 过程，根节点枚举不会长时间 STW，依赖 读屏障（Load Barrier） 进行对象引用跟踪：
  1. 短暂 STW，使用 OopMap 获取 GC Roots。
  2. 并发跟踪，利用读屏障监测对象访问，动态维护可达性信息。
  3. 由于所有扫描过程都在并发进行，STW 仅需 1~2ms。

(3) Parallel GC / Serial GC

  • 这些 GC 仍然依赖 STW 进行完整 GC Roots 扫描，但仍然利用 OopMap 进行优化。
  • Parallel GC 采用 多线程扫描 GC Roots，提高效率。
  • Serial GC 仍然是单线程扫描，适用于小型应用。
