jvm系列[20]-Java引用

发表于2026-10-14|更新于2026-10-14|3.jvm
|字数总计:1.2k|阅读时长:4分钟|阅读量:

无论是引用计数法还是可达性分析算法，判定对象是否存活都和引用脱不开关系。

Java 的四种引用类型（强引用、软引用、弱引用、虚引用）是 Java 内存管理的重要部分，主要用于控制对象的生命周期和垃圾回收行为。不同的引用类型适用于不同的应用场景。

1. 强引用（Strong Reference）

特点

  • 默认的引用类型，例如 Object obj = new Object();
  • 只要有强引用指向某个对象，该对象就不会被 GC 回收
  • 可能导致 OOM（OutOfMemoryError），因为 GC 绝不会 主动回收强引用对象

适用场景

  • 适用于大多数场景，例如：

  • 普通对象的声明和使用

  • 依赖 JVM 正常 GC 机制 管理对象生命周期

示例

回收条件：只有当 obj = null 或超出作用域，且没有其他引用指向该对象时，GC 才会回收它。

2. 软引用（Soft Reference）

特点

  • 当内存不足时，GC 会回收软引用对象，否则不会回收
  • 避免 OOM，适用于缓存
  • 需要使用 java.lang.ref.SoftReference 类

适用场景

  • 缓存系统（如 Java 内存缓存、图片缓存）
  • 允许在内存紧张时自动清理不重要的对象
  • 例如，图片加载框架（如 Glide、LruCache）使用软引用来缓存图片

示例

回收条件：当内存不足时，JVM 会优先回收软引用对象，以避免 OOM。

3. 弱引用（Weak Reference）

特点

  • 只要发生 GC，弱引用对象就会被回收
  • 需要使用 java.lang.ref.WeakReference
  • 比软引用更容易被回收

适用场景

  • 避免内存泄漏

  • 适用于缓存但不重要的对象（例如 ThreadLocal、WeakHashMap）

  • 监听器、观察者模式

  • 避免监听器不被回收导致内存泄漏

  • 动态代理

  • 例如 WeakHashMap，如果 key 没有其他强引用，GC 就会回收它

示例

回收条件：只要发生 GC，弱引用对象必定会被回收，适用于临时缓存。

4. 虚引用（Phantom Reference）

特点

  • 最弱的引用类型
  • **对象被 GC 回收时，会被放入 ****ReferenceQueue**，但 get() 方法永远返回 null
  • 必须和 **ReferenceQueue** 结合使用
  • 主要用于检测对象何时被 GC
  • 不能阻止对象被回收

适用场景

  • 监控对象是否被回收（类似于 finalize()，但更可控）
  • 管理堆外内存（如 DirectByteBuffer）
  • 确保对象被安全清理

示例

回收条件：当对象被回收时，**JVM 会把虚引用放入 ****ReferenceQueue**，以通知程序对象已被回收。

如何选择合适的引用类型？

  1. 强引用：一般情况下，普通对象应该用强引用，因为它们需要长期存在。
  2. 软引用：用于缓存对象，防止 OOM，比如图片缓存、数据库查询缓存。
  3. 弱引用：用于易回收的缓存对象，比如 WeakHashMap 作为临时缓存，或者防止监听器导致内存泄漏。
  4. 虚引用：用于监控对象何时被 GC，通常结合 ReferenceQueue，适用于资源释放或管理堆外内存（如 DirectByteBuffer）。
