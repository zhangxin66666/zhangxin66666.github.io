jvm系列[24]-常量池的概念

发表于2026-10-14|更新于2026-10-15|3.jvm
|字数总计:1.2k|阅读时长:4分钟|阅读量:

在 HotSpot 虚拟机 中，字符串常量池（String Pool）、运行时常量池（Runtime Constant Pool）和 Class 文件中的常量池（Class Constant Pool） 是三个不同但相互关联的概念。
它们在 JVM 的不同阶段发挥作用，我们可以按照 编译期 -> 运行时 -> GC 机制 来理解它们的关系。

1. Class 文件中的常量池（Class Constant Pool，字节码层面）

概念

  • 存储位置：Class 文件的**.class**文件结构（方法区 / 元空间）。

  • 作用：存储类在编译期间的所有符号引用（Symbolic References），包括：

  • 字面量（Literals）：字符串、数字常量（如 final static int a = 10）。

  • 符号引用（Symbolic References）：类名、方法名、字段名等（用来解析具体的运行时地址）。

  • 作用是支持运行时解析（Linking），类加载后，JVM 才会将其存入运行时常量池。

2. 运行时常量池（Runtime Constant Pool，方法区/元空间）

概念

  • 存储位置：

  • Java 8 之前：方法区（永久代 PermGen）。

  • Java 8 及以后：方法区（元空间 Metaspace，使用本机内存）。

  • 作用：存放类加载后解析出来的常量数据：

  • 从 Class 文件中的常量池加载。

  • 解析后的符号引用 -> 直接指向方法区、堆的实际内存地址。

特点

  1. 存储解析后的符号引用：
  • Class 文件的符号引用（如 java/lang/String）在类加载时，解析成实际的内存地址。
  1. 支持动态常量池（用户可在运行时向其添加数据）：
  • 运行时常量池支持 String.intern() 方法，将新的字符串加入池中。
  • Java 7 以后，运行时常量池的字符串存储在 Java 堆 而不是方法区。

3. 字符串常量池（String Pool，堆 Heap）

概念

  • 存储位置：

  • Java 6 及以前：存储在永久代（方法区），容易 OOM。

  • Java 7 及以后：存储在Java 堆（Heap），避免永久代 OOM 问题。

  • 作用：存储所有字符串字面量（String Literals）和**intern()**过的字符串，避免字符串重复创建。

  1. **new String("Hello")**创建的对象不会自动进入池：
  • new String("Hello") 在 堆 中创建新对象，而不会自动放入池中。
  • intern() 方法可手动存入池，返回池中的引用。

4. 三者的关系总结

运行时动态存入

总结

  • Class 文件常量池 是 .class 文件的一部分，存放编译时常量和符号引用，类加载时会被解析到 运行时常量池。
  • 运行时常量池 解析后存储真实的常量数据（符号引用、静态常量、动态常量），可动态扩展，部分数据（字符串）会存入 字符串常量池。
  • 字符串常量池 是存储 String 字面量和 intern() 过的字符串的池子，位于 Java 堆，主要用于优化 String 的重复创建。
